## 三层界面

微型默认窗固定 112×72 Qt 逻辑像素，14 逻辑像素标签字体，Qt 负责设备缩放。图标、短名称、下载/上传与关注/告警标记常驻；数值变化不改变窗体大小。长名称省略，完整信息在提示和展开卡片。权限或失效状态的 `!` 优先于关注圆点，关注本身不被取消。

卡片单实例，372×460 目标逻辑尺寸，受可用屏幕区域约束，内容溢出时在卡片内部滚动。悬停 350 ms 预览、联合区域延迟收起、点击保持与 Esc 收起分离。固定关注和选择入口保留在当前速率之后；选择菜单在一次打开期间冻结 key，不随刷新重绑。随后展示本次监控累计、Top 3 和详细/菜单入口。

详细窗口沿用原 MainWindow 的实时页面，仅将原 central widget 放入页签；保留 application → PID 树、原始数值排序、系统进程与当前联网筛选。新增累计页签独立列出全部 tracker 账户，包括已退出、无历史分类和同名不同 key 的账户，不从存活进程列表重建历史。切换页签不增加 Worker、Service、Collector 或定时器。隐藏累计页签只保存最新快照引用，显示时再增量同步。

原 Compact 保留，通过右键、卡片菜单或托盘切换；托盘恢复当前主模式。固定关注不等于窗口置顶。切换模式、开关卡片/详细窗口或取消关注均不重启采集、不重置累计。

## 数据和状态契约

`MicroProjection` 只读既有快照。自动候选沿用 SYSTEM 隐藏、UNKNOWN 保守显示，按原始上下行之和稳定排序。首次有效候选立即选择；当前对象仍正速率时挑战者连续领先约 2 秒才切换，归零时可立即切换。连续性只由收到的数据推进，心跳不伪造证据或平滑速率。

过期阈值 4 秒，采用可控单调时钟；可用数据或启动数据停止更新后明确过期。旧正速率通过 UI 副本屏蔽为 None，原快照和累计不修改。权限、失败与不可用优先保持具体原因。空列表、None、0、未运行是不同状态；Compact 的部分未知空态和计数也不再宣称全部空闲。

累计标题统一为“本次监控累计”，直接消费 `application_session` 原始字节。卡片仅接受精确可信 key，无法关联显示“无可信累计”；不使用名称或 PID 猜测。详细页按原始 Python 整数排序，包含大于 QVariant 常见整数范围的确定性测试。重复快照和元数据更新只替换展示，不加账、移账或合并同名账户。

`active_process_count` 标为最近关联进程数，而非当前联网进程数。不可用/过期时显示 —。当零关联计数同时存在未知创建时间的进程时，不能排除身份缺失，因此保守显示“进程状态未知”，不推断退出；只扫描一次枚举，不对每个历史账户重复扫描。可靠的新鲜零计数才显示未运行。

历史账户没有保存分类，累计页不臆造系统或第三方属性，也不套用实时筛选。首次归因 key 被内核固定；路径恢复后当前 key 与旧账户可能不相等，UI 不跨 key 追账。原始账户仍保留。关注、进程存活、当前流量、已确认累计相互独立。

## 内核与成本边界

`src/net_monitor/core/`、`collectors/`、`services/` 和 `ui/sampling_worker.py` 不变。ETW provider/解析/独立会话模式、PID/create_time 校验、原子退休交接、高水位及去重、约 2 秒测量窗口与约 500 ms 采样不改。新增 session_model/session_view 只承担展示，不新建累计器。

图标只做本地、可信路径、有界缓存和异步字节提取；结果校验选中 key，QImage/QPixmap 在 GUI 线程生成。UI 偏好只包括主模式、窗口位置与微型置顶。没有新增产品依赖、数据库、流量历史、遥测、品牌下载库或通知。小窗口不证明 CPU/内存降低，未做新同机性能对照，也不声称长期无泄漏。
