## 可带到另一台 Windows 的测试材料

携带产品 ZIP、Release 的 `SHA256SUMS.txt`、本文件和 [verify_windows_release.ps1](../tools/verify_windows_release.ps1)。不用安装 Python、Qt 或开发工具。完整解压 ZIP，保留 `_internal`；使用全新的解压目录，避免旧 CSV 等文件影响完整性检查。

在允许运行本地脚本的 PowerShell 中执行以下命令，按实际下载位置替换路径。脚本只读取 ZIP、解压文件和基本系统/屏幕信息，输出新的 JSON；不启动程序、不请求提权、不改变系统设置。系统策略阻止脚本时不要降低安全策略，可先手动使用 `Get-FileHash` 核对 ZIP，并记录未运行脚本的原因。

```powershell
.\verify_windows_release.ps1 `
  -ZipPath '.\NetMonitor-0.2.1.dev4-windows-x64-4bf4e02fce84-prerelease.zip' `
  -PackageDirectory '.\NetMonitor' `
  -ExpectedZipSha256 '640e10c7bd00cd71aff3030935421cbf674104e0f9941d80d0fcceda7d1af9f2' `
  -ExpectedSourceCommit '4bf4e02fce841a721f59f786e2f5fc8ec758db97' `
  -ExpectedVersion '0.2.1.dev4' `
  -OutputPath '.\windows-package-check.json'
```

哈希必须与可信发布页另行对照。脚本通过只证明文件一致；它会明确把干净机器、真实采集及物理多屏验收保留为未验证。JSON 不记录账户名、主机名或完整进程列表。报告在公开前仍应检查内容。

## 干净 Windows x64

使用新建 Windows 虚拟机快照或另一台未装 Python/Qt/开发环境的机器，记录系统版本、架构、虚拟或物理环境、屏幕缩放，以及是否预装其他运行库。仅新建用户账户不能证明系统无开发依赖。

2026-10-11，已在 VMware Workstation 25.0.1 中完成独立 Windows 虚拟机安装并进入桌面。配置为 4 vCPU、4 GB 内存、64 GB 动态磁盘、UEFI、Secure Boot、vTPM 和 NAT。官方 Windows 11 Enterprise Evaluation 简体中文 x64 安装 ISO 的完整 SHA-256 已与微软参考值核对；安装镜像的 WIM 元数据为 `10.0.26300.9457`，来宾实际安装版本和运行库基线尚未单独核验。

首次来宾副本出现 `python314.dll` 加载失败，用户反馈 `_internal` 为空或打不开。重新核对公开 ZIP，Python 和 VC 运行库均在包内；将同一份产品的全部 323 个文件展开为单独的测试光盘，逐文件核对后交给用户完整复制。随后用户确认窗口出现，桌面观察也确认 Micro、Compact 可见，Compact 显示绿色“运行中”。产品字节未变；没有据此认定产品代码缺陷，也未区分原副本缺文件与目录访问问题。完整复制整个 `NetMonitor` 文件夹并保留 `_internal`，无需另装 Python。

用户随后反馈“在虚拟机上表现良好”，明确要求跳过后续验证、进入下一步。本轮来宾测试在此结束，不再等待先前请求的 60 秒负载和 CSV。该反馈属于定性使用反馈：尚未取得来宾文件哈希、实际启动路径、权限令牌、定量负载与原生 CSV 对照、正常退出和重启的完整证据。以下清单保留供未来验收使用，不表示本轮已完成或仍要求用户执行；现有版本继续为未签名 Pre-release。

1. 从公开 Release 重新下载并核对上述 ZIP；完整解压到含中文、空格的目录，使用普通权限启动。通过条件：无需开发环境即可出现窗口，没有缺 DLL、Python 或 Qt 插件错误。
2. 确认 Micro 和 Compact 能显示权限状态，切换模式、打开 Card 和详细信息；在普通权限下不能把未知流量显示成已测得零。
3. 由测试者点击管理员重启并处理 UAC。先取消一次，确认仍能操作；再次同意，确认旧实例退出、新实例正常采集。记录具体结果，不把看到窗口等同于已取得管理员权限。
4. 用已知客户端产生有边界的上下行流量，记录负载工具的原始字节数、起止时间及进程身份。详细信息搜索该应用，导出本次监控累计，隐私标识选项保持关闭。检查上传/下载与负载是否一致，并记录同时使用同一应用产生的其他流量；不要拿格式化速率猜精确字节数。
5. 检查搜索、排序、取消导出、退出进程保留累计，以及导出结果。退出应用后从 Compact“窗口 → 退出”结束监控，确认进程消失。再次普通启动，确认无需手工清理旧实例/会话。

如果启动、归属、采集或退出失败，保留版本、最小步骤与原始错误，修复后重验受影响项。不要关闭 Defender、SmartScreen 或 UAC 来取得“通过”。

## 真实多屏与缩放

| 操作 | 通过条件 |
| --- | --- |
| 在两屏之间移动 Micro、Card、Compact 和详细信息 | 窗口可操作，字体及上下行/导出控件可读；不落到不可访问区域 |

| 运行时断开/重接副屏、变更主屏 | 窗口可恢复、没有崩溃，记录恢复方式和结果 |
| 改变屏幕缩放后重新启动并再次跨屏 | 没有持续的裁切、错位或不可操作控件 |

## 长时间观察与签名

本次 2 小时观察固定最终 EXE 的身份及资源，已分别核对起止负载、最终累计 CSV、末尾导出交互、正常菜单退出和 ETW 会话清理。程序存活和末尾交互不能证明 GUI 全程响应、采集没有停顿或没有内存泄漏。资源报告列出首尾区间及峰值；后续观察仍应单独记录进程退出、身份变化、采样权限错误或休眠造成的长采样缺口。

签名另起发布步骤：确定发布者身份和可用签名服务后，对最终构建执行签名及时间戳验证，再重新生成文件清单、ZIP、校验和，并验证新的实际发行包。不能给已公开 ZIP 换字节、沿用旧哈希，或把第三方 DLL 自带签名当作 Net Monitor 已签名；证书和密钥不写进仓库或聊天。

可选择代码签名证书或适用的托管签名服务；例如 Microsoft Artifact Signing 的公开信任配置需要验证发布者身份，配置与签名角色分别授权，当前未假定本项目已具备资格或已开通服务。[Microsoft 资源和角色说明](https://learn.microsoft.com/en-us/azure/artifact-signing/concept-resources-roles)

选定服务后，按其要求使用 SHA-256 文件摘要和 RFC 3161 时间戳，并用 `signtool verify /pa /all /v NetMonitor.exe` 验证普通应用的签名链，另外核对时间戳与发布者。`/fd`、`/td`、`/tr` 及验证策略的含义以 [Microsoft SignTool 文档](https://learn.microsoft.com/en-us/windows/win32/seccrypto/signtool) 为准。签名验证成功不等于所有 Windows 环境都不会出现安全提示。
